## 5. 目標アーキテクチャの決定事項

各項目に推奨とオーナー判断の要否を書く。
「確認のみ」の項目は推奨既定値で仮置きし、Phase 0 の PRODUCT.md レビューで変えてよい。
Q4〜Q6 に当たる項目は、回答 (10 章) を反映して「決定」とした。

**画素の正本**
- 決定 (Q4 の回答): CPU 上の疎な 256px タイルストアを唯一の正本にする (RGBA8 premultiplied、`Arc<Tile>` による copy-on-write、空タイルは持たない)。ダブ描画・合成・塗りつぶし・書き出しはすべて CPU で行い、rayon でタイル単位に並列化する。GPU は表示専用で、正本へ読み戻す経路は持たない (GPU ストローク描画を採った場合の StrokeEnd の読み戻しだけを除く)。性能のゲート (Phase 1 のスパイク (d) か Phase 2 の P2) に落ちた場合に限り、処理の一部を GPU に移す。
  - ダブ描画が遅い場合は「GPU ストローク描画」を採る。描画中の 1 本だけを GPU 上の一時的なストロークバッファに描き、画面にはレイヤーとストロークバッファを重ねて表示する。StrokeEnd で、ストロークバッファのうち変わったタイルだけを読み戻し、CPU の正本へ 1 回で合成して確定する。これが 1 つの履歴エントリになる。ストロークの途中に届いたコマンドは、確定の後に適用する。この代替を採ったら CPU のダブ描画は持たず、ブラシの実装を 1 つにする。採るときの改訂 (6 章 Phase 1 の (d) か Phase 2 の P2) では、読み戻しを同期にするか非同期にするか、StrokeEnd の前後で表示が変わる量の許容値、確定にかかる時間の上限を決める。
  - 再合成が遅い場合は、表示用のページ合成を GPU で行う。
  - どちらの場合も、確定した画素と正本は CPU に置く。GPU が正本を持つ時点は作らない (R1〜R5 の原因は、正本が CPU と GPU の 2 か所にあったことである)。
- オーナー判断: 済み (Q4)。ダブ描画が遅い場合の代替を GPU ストローク描画にすることも、オーナーが決めた。SKETCH:524「GPU 中心、CPU フォールバックあり」からの変更である。

**ID**
- 推奨: 作品ごとの単調増加 u64 アロケータ。型付きの `Id<T>` で表し、削除した ID は再利用しない。次に振る ID は作品メタデータに保存する。index は UI の表示順にだけ使う。新規作成・読込のたびに epoch を進め、epoch の違う履歴やジョブ結果は捨てる。
- オーナー判断: 不要。

**変化の伝え方**
- 推奨: 状態を変える入口は `update(&AppState, AppCommand) -> (AppState, ChangeSet, Vec<Effect>)` の 1 つだけにする。ドメインの apply は構造共有を使う純関数とし、ChangeSet (触れた ID、タイル集合、revision) を返す。派生状態はすべて ChangeSet と revision だけを見て更新する。パネルへの状態の渡し方と、パネルからの操作の受け取りは、「UI 技術」に書く 1 経路だけにする。
- オーナー判断: 不要。ただし AppCommand の一覧 (パネルの Action の一覧を含む) はオーナーが読んで承認する (理解負債への手当て)。

**ドメインモデル**
- 決定 (Q5 の回答): 作品 → ページ → コマ → レイヤーの階層を保つ。ページは判型と、断ち切り・ノド・小口・セーフエリア・見開きの設定を持つ (賢いスナップ SKETCH:159-166 と入稿の基準になる)。レイヤーはページ座標のタイル格子に置く。コマはフレーム形状を持つグループで、配下のレイヤーをクリップする。レイヤーごとに `clip_to_koma=false` を指定でき、コマからはみ出す描画 (SKETCH:103-104) を表現できる。コマの移動・リサイズは画素に触れない。テキストは TextObject として第一級の要素にする。Document・EditorState・Catalog は分けて持つ。不変条件はコンストラクタと apply で守る。
- オーナー判断: 済み (Q5)。

**Undo**
- 推奨: すべての文書コマンドを対象にする。before / after の文書ルートを差し替える方式で、上限は保持バイト数 (既定 1GiB)。ストロークは明示的な StrokeBegin / End / Cancel で閉じる。履歴表示には対象のコマとページを出す。
- オーナー判断: 確認のみ。

**UI 技術**
- 決定 (Q6 の回答): すべてのパネルを同じ仕組みで動かす。同梱パネル (アプリに入っている 12 個など) と外部パネル (外部フォルダから読み込むもの) の違いは、同梱されているかどうかだけとする。パネルは見た目を HTML と CSS で、振る舞いを Wasm (Rust で書く) で持つ。ホストは Blitz (blitz-dom / blitz-html / blitz-paint。vello で wgpu のテクスチャに直接描く) で表示する。JavaScript は使わない。旧コードの表示部 (panel-html)、Wasm の実行部 (panel-wasm-host)、panel-protocol の ABI 定数、panel-sdk、panel-macros は移植し、パネルとホストの接続は作り直す (7 章)。
- パネルとホストの接続:
  - 状態: ホストは、パネルが購読した型付きの状態 (区分ごとの view-model) のうち、ChangeSet と revision から変わったものだけを送る。JSON 文字列を入れ子にした host state や、呼び出しごとの全量の複製は持ち込まない。
  - 操作: パネルは型付きの Action を発行する。ホストはそれを AppCommand に変換して update の入口に入れる。旧コードの翻訳器、文字列の要求経路、`altp:` のミニ言語は持ち込まない。
  - 結び付け: DOM の要素とハンドラは、要素の属性 `data-on-<イベント名>="<ハンドラ名>"` (例: `data-on-click="undo"`、`data-on-input="set_brush_size"`) で結び付ける。イベント名は DOM のイベント名 (click・input・change・keydown など) とする。値 (スライダーの値、入力された文字列、選んだ項目) は DOM のイベントから取り、ハンドラの型付きの引数で渡す。リストの項目は安定 ID を `data-id` 属性に持ち、クリックではその値をハンドラに渡す (旧コードの `data-args` は、この `data-id` に置き換える)。旧コードの `altp:` の解釈 (panel-html の parse_data_action) と出力 (panel-sdk の render_action_list) は、この形式に置き換えて移植する。扱うイベント名の一覧は Phase 2 の最初のパネルの PR で決め、Action の一覧と一緒にオーナーが承認する。
  - Wasm の状態: ハンドラの中で書いた状態を、同じハンドラの中で直後に読めるようにする (read-your-writes)。Wasm のトラップは握り潰さず、ログに残してエラートーストで知らせる。
  - 作る順序: Phase 2 で最小構成 (ツールと色の区分の view-model と Action、Action から AppCommand への変換、ポインタ・ホイール・キーの配線、結び付け、read-your-writes、トラップの記録) を作る。Phase 4 で IME の配線を、Phase 5 で残り (ほかの区分の view-model と Action、パネル設定の永続化、z-order を含む配置) を作る。
- 入力 (R12 の手当て):
  - ホストは、ポインタ (座標付き)・ホイール・キー・IME (未確定文字列と確定) を、フォーカスのあるパネルの DOM に届ける。スライダー・テキスト欄・select の値は、DOM のイベントの値としてハンドラに渡す。
  - IME の候補窓は、フォーカスのある要素の矩形を winit に渡して、入力位置の近くに出す。テキスト欄にフォーカスがある間は、ホストのショートカットを発火させない。
  - Blitz が標準で扱えない部品 (スパイク (a) で確かめる) は、panel-sdk の部品としてポインタ処理で作る。
  - パネルの矩形と重なり順 (z-order) の正本を 1 つにし、描画の順とヒット判定の順を一致させる。パネル上のポインタ入力はキャンバスへ渡さない。`id` 属性を持たない要素 (リストの項目など) もヒット判定の対象にする。
- 配置とテーマ: panel-workspace (4 隅のアンカーによる配置、8 ハンドルのリサイズ) を移植し、z-order を足す。UI プロファイルは配置状態とパネル設定のシリアライズとする。ADR 019 の決定 (共有テーマ CSS、アイコンフォント、`default_size` と `preset.size` の一本化、presenter の scissor、DPI 対応) を引き継ぐ。
- 依存: blitz 系は `=0.3.0-alpha.2` で固定する。wgpu の版は vello に合わせる。パネルで CJK が表示できることはスパイク (a) で確かめる。
- SKETCH との関係: SKETCH は次の 3 点を定めている。
  - 描画フレームワークと UI ランタイムを内製し、パネルはホスト定義の中間表現で表示する (SKETCH:449-453)。
  - JavaScript / Web フロントエンド技術は採用しない (SKETCH:453)。
  - 標準パネルは、MVP ではまず本体モジュールとして実装する (SKETCH:231)。

  Q6 の回答は、これを次のように変える。中間表現には HTML (DOM) と CSS を使い、表示は Blitz に任せる。JavaScript は使わない。同梱パネルも、最初から外部パネルと同じ Wasm の仕組みで動かす。PRODUCT.md にこの変更を書く。
- 比較 (Q6 の判断材料):

  | 選択肢 | 工数 | IME・入力 | 学習としての面白さ (SKETCH:40) | 見た目の自由度 |
  |---|---|---|---|---|
  | Blitz (HTML/CSS) の継続 (採用) | 中〜大 (表示と Wasm の実行の約 5.5k 行は移植する。入力の配線・IME・select と、パネルとホストの接続は作り直す) | ホストで配線し直す。alpha 版の不具合が残りうる (スパイク (a) で確認) | 中 | 高い (CSS)。SKETCH:453 は変更する |
  | 全パネルを Wasm にし、Wasm が返す宣言的 UI ツリーを egui で描く | 中 (UI ツリーの protocol・レンダラ・SDK で約 3k 行。付録 D panel-system の見積もり。12 パネルは書き直す) | egui が標準で持つ | 中 | 低い (CSS のようなスタイリングは無い) |
  | SKETCH どおりの内製ランタイム (中間表現を自前のウィジェットで描画) | 大 (テキスト入力と IME だけで数週) | 自前で実装する | 高い | 高い |

- オーナー判断: 済み (Q6)。スパイク (a) が不合格なら、再試行 (a') の第一候補は表の 2 行目とする (6 章 Phase 1)。どちらでも「全パネルを同じ扱いにする」は保つ。配置の方式 (旧コードと同じアンカー配置) は確認のみ。

**プラグイン**
- 決定 (Q6 の回答): 外部フォルダからのパネルの読み込みは Phase 7 で開放する。それまでは同梱パネルだけを読み込み、ABI は自由に変えてよい。同梱パネルは最初から外部パネルと同じ ABI で動かすので、Phase 7 で足すのは次のものになる。
  - 外部フォルダからの読み込みと、ABI の版の検査
  - 許可リストの Action に限る権限、fuel / epoch による打ち切り、ResourceLimiter。これらは同梱パネルにも同じく当てる
  - パネル以外の拡張点 (フィルタ・入出力・テンプレート生成・バッチ)
- オーナー判断: 済み (Q6)。

**保存**
- 推奨: SQLite の単一ファイルに新スキーマ v1 で保存する。内容ハッシュで引くタイル blob、安定 ID をキーにしたエンティティ表、koma_versions を持つ。保存は差分だけを 1 トランザクションで書き、既存ファイルは消さない。起動時に integrity_check を行う。format_version はスキーマを変えるたびに必ず上げる。読めなかったファイルにパスを紐付けない。UI 状態は原稿ファイルに入れない。旧アプリ (legacy) の形式からの移行ツールは作らない。新スキーマの版の扱いは 2 段階にする。
  - v0.2 (オーナーが実原稿を描き始める時点) より前: 旧版は明示的なエラーで拒否してよい。ファイルは試用データとして扱う。
  - v0.2 以降: スキーマの変更は追加だけに限る。format_version を上げたうえで、1 つ前の版からの移行の段を足す。移行の段は連鎖させてすべて残し、v0.2 以降のどの版のファイルも最新版まで順に移行して開けるようにする。追加だけの変更なので、各段は既定値を補う程度の小さなコードで済む。v0.2 以降の各版のフィクスチャファイルをリポジトリに残し、移行テストではそのすべてが最新版で開けることを確かめる。フィクスチャは、最小の作品 (1 ページ・1 コマ・数タイル) に、その版のスキーマで永続化するエンティティの種類 (Phase 4 の ADR 021 で凍結する一覧と、それ以降に追加した種類) を 1 つずつ含めて作る。アプリの操作で作れない種類 (コマの版など) は、store の API で作ってよい。移行コードは「後方互換コードを残さない」規約の唯一の例外とする。
- オーナー判断: 確認のみ (残したい旧原稿が無いか)。

**非同期**
- 推奨: AppState は UI スレッドだけが持つ。重い処理は JobRunner (std::thread と rayon) で行い、入力には Arc による不変スナップショットを渡す。完了は EventLoopProxy で UI スレッドへ戻し、epoch と revision を確かめてから適用する。同種のジョブは直列化し、取消と進捗を持たせる。tokio は使わない。
- オーナー判断: 不要。

**テキスト**
- 推奨: fontdb、rustybuzz ('vert' / 'vrt2')、swash と自前の縦組みレイアウトで組む。MVP の範囲は SKETCH:311-316 (縦書き/横書き、改行、ボックスと吹き出しへの流し込み、フォント・サイズ・太字) に限る。ルビと高度な禁則は後回し。フォントに無い文字は警告を出す。
- オーナー判断: 確認のみ。

**入力**
- 推奨: 入力は `PenSample { pos: f32, pressure, tilt?, eraser?, timestamp }` に正規化する。傾きと消しゴム側は最初から省略可能なフィールドとして持ち、後から入力層を作り直さずに済むようにする。
- オーナー判断: 確認のみ (傾き・消しゴム側・ホバーが MVP に要るか)。

**テスト**
- 推奨: 本番と同じ経路を通す。ペイント・合成・保存は CPU の本番コードをヘッドレスでそのまま動かす。受け入れテストは Driver (ユーザー操作の語彙だけを公開する層) を通して書き、受け入れ ID を名前に付ける。UI も Driver から確かめる。Driver はパネルをヘッドレスで動かし (Blitz の DOM と Wasm を実際に動かす)、入力イベントを送って、DOM の状態と発行された Action を見る。GPU は fallback アダプタでの golden テスト (presenter とパネルの描画) で確かめる。GPU ストローク描画 (「画素の正本」) を採った場合は、ブラシのテストも fallback アダプタで動かす。ほかに proptest、障害注入、perf ジョブを持つ。GPU アダプタが無ければ失敗させ、`ALTPAINT_ALLOW_NO_GPU=1` のときだけ飛ばす。catch_unwind でアサートを握り潰すことは禁止する。
- オーナー判断: 不要。

**観測性**
- 推奨: tracing でファイルにログを出し、panic hook でクラッシュログを残す。ユーザーに見せるエラー経路 (トースト) を Phase 2 で入れる。トーストはホストが Blitz で直接描き、パネルの仕組みは通さない (Wasm のパネルが止まっても知らせられるようにするため)。本番コードでの eprintln は禁止する。
- オーナー判断: 不要。

**クレート構成**
- 推奨: ライブラリ 14、同梱パネル (パネルごとに 1 クレート)、バイナリ 1 (apps/altpaint) とする。
  - ライブラリは geom / raster / doc / paint / text / store / pen-io / editor / gpu / ui / panel-host / panel-protocol / panel-sdk / panel-macros。
  - ui は、Blitz による表示・入力の配線・パネルとホストの接続を持つ。panel-host は、wasmtime と DOM を書き換える host function を持つ。panel-workspace は editor に移植する。
  - gpu・ui・panel-host・apps 以外 (同梱パネルを含む) は、wgpu / winit / blitz 系 / vello / wasmtime に依存しない。panel-protocol はほかのローカルクレートに依存しない。
  - これらを CI の依存規則テスト (cargo metadata) で検査する。クレート数の検査は、同梱パネルを除くライブラリとバイナリの数 (14 と 1) に対して行う。
  - 同梱パネルは `panels/` の下に置き、依存規則テストとビルドスクリプトはこのパスで同梱パネルを見分ける。Driver と受け入れテストは apps に置く。apps は Driver のために lib と bin の両方のターゲットを持ってよく、クレート数の検査ではバイナリ 1 として数える。
  - Phase 7 でもクレートは足さない (外部パネルの読み込みは panel-host に入れる)。
- オーナー判断: 構成を変えるには ADR とオーナーの承認が要る。

**性能目標 (仮)**
- 推奨: 既定ページ 2894×4093・10 レイヤー。100 ページの作品で RSS 2GiB 以下、VRAM 1GiB 以下 (ページ単位の遅延読込を前提とする)。開発機は RTX 2070。Phase 4 の計測後に PRODUCT.md で確定する。
- オーナー判断: 確認のみ。

**リポジトリと OS**
- 推奨: 同じリポジトリの main 上で作業し、旧コードは `legacy-final` タグから参照する。一次対象は Windows、Linux は CI でのビルドとヘッドレステストだけ、macOS は MVP の対象外。
- オーナー判断: 確認のみ。
